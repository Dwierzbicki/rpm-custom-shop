# Back office UI standard
Dark neutral navigation, distinctly lighter work panels, inset fields and table header. Red is reserved for primary action and active navigation. Consistent list / open / edit / save / return, compact status and search. Power Guides engine and dyno records are mutually exclusive list/editor states. Internal tabs retain drafts; browser reload/close uses beforeunload. In-app navigation outside Power Guides is not globally guarded yet. Preserve APIs and data. Shared contrast CSS affects authenticated admin only; no storefront styling changes. Validate responsive appearance on actual desktop/mobile before wider refactor. Recommendations now follow the same list/editor pattern with isolated single-record drafts, explicit save/delete, separate global discount editor, failed-read write protection and compare-and-swap against the loaded settings. Other modules retain existing behavior for now.

Navigation standard: Dashboard, Sales, Catalogue, Suppliers, MotoLab, Settings, collapsed Tools (audits). All existing 16 destinations retained; most-specific route matching, accessible current-page markers and mobile Escape close. Settings hub only lists store settings, future features collapsed. No permissions or API changes. Validate actual responsive view after deploy.

## Business consolidation
Six sidebar workspaces with route-based tabs, no duplicated data or APIs. Quality center groups descriptions, image audit and link audit; existing routes remain canonical. Sales includes orders and quotes; email preview opens from the selected order. Settings contains company, payments, shipping, appearance and homepage Community; planning-only placeholders removed from UI. MotoLab status is folded into Research, old builder deep link stays accessible. Pricing hub distinguishes actual catalogue price rules, manual RPM prices, supplier proposals, guide prices and simulation only; no price calculation, VAT, checkout, or publication change. Existing FMIC internal tabs are preserved. Roadmap: unify pricing after verifying source price basis and actual purchase/shipping cost. Browser behavior and cross-route unsaved changes need E2E verification.
