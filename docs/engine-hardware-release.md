# Engine Hardware — production release contract

The current release manifest is deliberately null. Do not merge a preview as a complete catalogue. The validator checks structural consistency and evidence presence, not the truth of the evidence. A competent reviewer must compare all model/market/production profiles against licensed ETK/EPC exports and workshop procedures before attesting scope or exact mounting.

## Source acquisition
- BMW: https://aos.bmwgroup.com/ — request commercial reuse/export entitlement for WebEPC and corresponding AIR/TIS specifications, including original exploded diagrams and permission for interactive overlays.
- Toyota: https://www.toyota-tech.eu/ — request an authorized EPC and repair-information source for 2JZ GE/GTE (both VVT-i variants and relevant markets). Do not assume a service-information subscription grants republication.
- https://www.tecalliance.net/products/cards/tecdoc-catalogue — evaluate licensed commercial data/API, confirm exact historic model coverage, original images and right to redistribute. No assumption that its aftermarket data covers every OEM fastener.
- https://www.partslink24.com/ — evaluate ordering/parts-data agreements and commercial reuse separately. Availability of a catalogue or subscription is not evidence of a licence to republish.

RealOEM pilot reference pages were rechecked 2026-11-28: 11_9921, 11_9907, 11_9953. Its notice explicitly objects to mass copying and commercial resale. Do not scrape it or reproduce illustrations. Three additional reference pages illustrate why the release must distinguish a set of cylinder-head bolts from individual bolts and handle discontinued parts and production conditions: 11_9905, 11_9908, 11_9913. No new bulk records or drawings are included.

## Delivery format
Set app/engine-hardware/release.json to a reviewed HardwareRelease (see release.ts). Include all 20 agreed engine variants, each with explicit vehicle, market, production range and source evidence. Each profile must account for all 29 checklist assemblies; non-applicable items require evidence. Identify parts by manufacturer + OEM, not dimensions; each profile/diagram position maps to one unambiguous fitment. Alternatives must be modeled as separate profiles with documented applicability. Include the quantity unit (piece or set), technical evidence, exact mounting description, torque or documented non-applicability, replacement procedure, actual original image hotspots, and original source identifier. Every item has either an explicit active store SKU or a localized reason why it is not offered. Store approved images in public/engine-hardware/licensed, with SHA-256 and rights evidence. The server verifies all image bytes before enabling the release. No external image hotlinking.

Release metadata must reference review, rights and scope evidence. It does not replace licensing or technical review. Keep contract references nonconfidential in the public repository. Private legal contracts and proprietary source dumps must not be committed to this public repository; move release storage to a restricted licensed data service if the agreement prohibits source distribution. The release manifest must not contain credentials or confidential documents. Do not publish until the intended distribution method is permitted.

The storefront uses the release data and filters by explicit profile. The existing cart only offers visible, non-configurable manual products whose live catalog price and availability are verified. No inferred offers or prices. A missing or invalid release remains unavailable unless the explicitly labelled preview is intentionally enabled. Neither staging import nor admin readiness display publishes data. Future authorized import transformation and supplier/price validation must precede final release.
