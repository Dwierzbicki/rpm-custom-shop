# MotoLab knowledge editor
Private admin-only records are stored in the existing rpm_shop_settings table under motolab_knowledge_v1:engine: and :technical: prefixes. No production migration is executed. The previously proposed normalized technical evidence table remains a future migration; do not dual-write. The initial list returns the latest 200 per kind, with a truncation notice.
Each save creates a draft and clears approval; separate explicit review requires a reason. Optimistic revision checking prevents silent concurrent overwrites. For technical records, server resolves exact SKU in the selected FMIC/manual catalogue and snapshots name, brand, MPN, EAN and category at save; approval rechecks identity. Approval is a point-in-time operator review, not live validity, and not a fitment or safety certificate. No new public endpoint, no automatic changes to storefront rules. No AI or external fetch is active. Source links are user-entered and never fetched by server. Unknown geometry stays null. Workshop references can be non-web; other sources require HTTPS.
Next: paginated search, immutable revision audit, normalized evidence migration with backup, source-specific evidence fields, research API with explicit cost limits, reviewed evidence integration with current-catalog identity checks.
